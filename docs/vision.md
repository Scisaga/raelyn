# Raelyn V2 产品愿景

## 文档职责

本文只定义 Raelyn V2 要成为怎样的产品，以及用户最终应获得怎样的体验。它不以当前页面、接口或表结构为产品上限。

- V2 的完整页面关系与交互上下文见 [V2 信息架构](product/information-architecture-v2.md)。
- 核心界面的空间结构与交互节奏见 [V2 核心界面线框规范](ui/wireframes-v2.md)。
- 当前实现事实与目标能力之间的差距见 [V2 现状能力差距](product/capability-gap-v2.md)。
- 当前代码行为仍以 [架构总览](architecture/overview.md)、[REST API](api/rest.md)、[数据模型](architecture/data-model.md) 与 [事件语义星域](architecture/event-graph-analysis.md) 为准。

产品目标、现状差距和交付方式必须分开维护：现状决定从哪里出发，风险决定实施顺序，但二者都不降低产品定义。

## 核心判断

Raelyn 已经不再是一个加入 AI 功能的视频下载器。

它要成为一张持续演化、可以回到证据的私人语义宇宙：系统长期观察用户选择的世界，把不断到来的公开视频转化为真实事件、主题结构和故事轨迹，并让用户看见这个世界如何变化。

下载、转写、任务和信源管理是观测站的基础设施；事件语义星域才是用户理解世界的主要操作空间。

## 产品定义

**Raelyn 是用户的私人语义观测站。**

一句话定位：

> Raelyn 持续观察你选择的公开信源，把散落在视频中的事实凝结成会生长的事件星域；你可以回放变化、追踪故事，并从任意结论返回原始证据。

V2 的三个核心承诺：

1. **看见变化**：不只告诉用户新增了多少内容，而是让新事件如何进入星域、主题密度如何变化、故事如何延伸变得可见。
2. **形成理解**：把重复报道归并为真实事件，把有证据的延续关系组织为故事，把周期性解释组织为简报。
3. **回到证据**：星点、故事与简报中的每个事实都能下钻到事件记录、转写片段和原始来源。

## 北极星体验

用户重新打开一个长期观测域时，不应先看到文件数、任务数或服务占用，而应立即回到上次离开的语义世界：

1. 星域停留在上次观察的位置与时间窗口；
2. 用户播放从上次观察到现在的变化；
3. 新事件依发生时间进入，星群的疏密和主题边界随之显现；
4. 有新成员、新证据、响应或纠正的故事航迹被点亮；
5. 用户点击一处变化，进入真实事件或故事；
6. 继续下钻到证据片段、转写位置和原始视频；
7. 简报作为当前星域的解释层，帮助用户理解变化，而不是成为一篇与星图割裂的 Markdown。

这个过程是 V2 的主叙事。列表、筛选和管理页面都服务于它，而不是与它争夺产品中心。

## 语义宇宙的概念系统

| 产品概念 | 用户理解 | 产品职责 |
| --- | --- | --- |
| 观测域 | 用户长期关心的一个世界 | 定义信源范围、关注问题、时间记忆与独立语义空间 |
| 星域 | 这个世界的语义地理 | 承载主题结构、真实事件和稳定空间记忆 |
| 星点 | 一件真实事件 | 聚合描述同一事实的多条事件记录 |
| 星群 | 一个主题区域 | 表达一组语义邻近事件的结构，不暗示因果 |
| 航迹 | 一条持续发展的故事 | 连接有证据的延续、原因、响应或纠正关系 |
| 时间轴 | 这个世界如何展开 | 回放事件发生、星域密度变化和故事延伸 |
| 变化层 | 自上次观察以来发生了什么 | 展示新增事件、故事更新、新证据、纠正与身份变化 |
| 证据 | 为什么相信一个星点或关系 | 连接事件记录、原文片段、转写位置和来源记录 |
| 观测简报 | 对某个时间切片的解释 | 用结构化引用解释当前星域及其主要变化 |
| 信源 | 观测站使用的仪器 | 定义持续监听哪些频道或账号 |
| 来源记录 | 原始观测档案 | 保存视频、字幕、转写、资产和平台元数据 |

宇宙隐喻只服务于空间理解与品牌记忆。涉及事实、时间、证据和系统状态时，界面继续使用明确、可验证的产品语言。

## 产品主循环

```text
建立观测域
→ 选择信源与关注问题
→ 系统持续感知并形成事件
→ 星域更新并计算自上次观察以来的变化
→ 用户回放星域演化
→ 进入故事或真实事件
→ 回到证据与原始来源
→ 通过简报形成阶段性理解
→ 调整观测范围并继续长期观察
```

这个循环同时包含“机器持续观测”和“人形成理解”。前半段可以异步运行，后半段必须让用户始终知道自己看到的是什么、为什么出现、依据来自哪里。

## 星域是主操作空间

V2 的默认首页就是当前观测域的星域观测台，不再额外设计一个以卡片和统计为中心的仪表盘。

星域观测台同时承载四种观察方式：

- **空间观察**：从星群、主题和密度理解领域结构；
- **时间观察**：播放一个时间窗口，观察事件出现和结构累积；
- **故事观察**：点亮一条航迹，理解事件如何延续、响应或被纠正；
- **证据观察**：从任何星点、关系或简报引用回到原始材料。

“新发生”“新进入星域”“故事更新”“待审核”不再是首页上的独立统计卡，而是叠加在星域上的观察流和变化层。事件列表仍然存在，但它是同一组对象的线性替代视图，不是另一个产品中心。

## 来源播放是独立的时间复盘工作台

星域中的时间回放用于观察真实事件、主题密度和故事关系如何演化；来源播放用于按日连续复盘当前观测域已经收录且可播放的原始记录。二者共享观测域和时间上下文，但不互相替代。

来源播放工作台必须保留三个连续协作的核心区域：

- 按日滑动的来源日历；
- 当日可播放来源记录列表；
- 播放器、转写与前后记录控制。

它不是资料库详情页的放大版，也不承担观测域、信源、简报或数据处理配置。资料库回答“系统保存和管理了什么”，来源播放回答“这一天收录的原始材料讲了什么”。

## V2 必须建立的产品能力

### 持续身份

- 真实事件拥有跨快照可延续的身份；
- 合并、拆分、退休和重新出现都有可解释的谱系；
- 故事拥有稳定身份，快照只产生故事的新版本，而不是一批无法连续阅读的新 ID；
- 用户的关注、阅读位置和返回路径绑定稳定身份，不绑定一次性快照对象。

### 星域变化

- 系统记录用户最后观察游标；
- 相邻快照之间产生可查询的变化集；
- 变化至少区分：新事件、新进入星域、事件更新、故事新增成员、新证据、响应、纠正、合并与拆分；
- 时间播放展示事件发生过程，变化层展示系统认知发生了什么变化，二者不混为同一时间口径；
- 坐标继承、局部调整和全量 rebase 对用户可解释。

### 故事轨迹

- 故事不是快照中的临时连线，而是可以长期回访的第一等对象；
- 每次更新都能说明新增了什么事件、证据或关系；
- 用户可以从星域点亮故事，也可以从故事时间线返回星域中的位置；
- 生成性故事摘要只解释结构化成员与关系，不篡改事实层。

### 结构化证据

- 真实事件、故事关系和简报段落使用稳定引用；
- 证据定位到标题、描述或转写的明确片段；
- 来源记录详情可以反向列出它支撑的事件、故事与简报；
- 任何 AI 解释都标明生成口径和引用范围。

### 星域简报

- 简报描述一个明确时间窗口和快照口径；
- 正文中的事件、故事和来源是可交互引用；
- 点击引用可在星域中定位并恢复相同时间上下文；
- 从星域选中的主题或故事可以打开相关简报段落；
- 简报是理解星域的叙事镜头，不是独立内容孤岛。

## 产品层级

### 认知层

用户直接感知价值的层级：

- 事件语义星域；
- 星域变化与时间回放；
- 真实事件；
- 故事轨迹；
- 观测简报；
- 证据验证。

### 感知层

把公开内容转化为可分析材料：

- 信源同步；
- 下载与资产管理；
- 字幕、ASR 与 transcript；
- 事件抽取、审核、向量与归并。

### 运行层

维持观测站长期运行：

- Job、Worker 与 Scheduler；
- 数据库、对象存储和模型服务；
- 失败、重试、暂停和资源观测；
- MCP 与外部智能体接入。

正常情况下，感知层与运行层退到背景；当证据缺失、数据异常或系统失败时，它们在当前上下文中浮现并提供可行动入口。

## 产品原则

### 变化优先于库存

用户首先看到世界发生了什么变化，而不是系统保存了多少文件。库存与吞吐只在管理和排障时出现。

### 空间连续性形成记忆

星域不是每次打开都重新洗牌的数据图表。语义坐标应尽量连续，让用户逐渐记住主题在哪里、故事从哪里延伸；无法保持连续时必须明确解释 rebase。

### 时间与空间共同叙事

三维坐标表达语义邻近，时间轴表达事件发生。时间改变星点的可见与变化状态，不偷换 X/Y/Z 的含义，也不通过镜头漂移制造虚假的演化。

### 故事必须由证据连接

普通语义邻近只形成主题，不自动形成故事。航迹只表达可追溯的 continuation、causes、response 或 corrects 关系。

### 证据是系统底座

摘要、真实事件、故事和简报都必须能回到事件记录与原始来源。AI 负责提炼和解释，不拥有改写事实的权力。

### 不确定性可见

待审核、证据不足、时间不精确、身份合并或拆分都应成为可理解的产品状态，而不是被静默隐藏或用视觉效果掩盖。

### 基础设施按需浮现

正常状态不让任务、存储和服务健康占据主界面；异常状态必须能够从受影响对象一跳进入处理位置。

### 诗意不虚构数据

可以使用星域、星群和航迹建立想象力，但不能添加装饰星点、虚构关系、无依据的趋势或被误认为事实的动画。

## 目标用户

Raelyn 面向需要长期跟踪公开音视频信源的个人研究者、分析者和深度信息消费者。他们不是来管理下载队列，而是希望：

- 以自己的问题组织长期观测，而不是接受平台推荐；
- 快速发现跨来源重复报道背后的真实事件；
- 理解一个事件如何延续成故事；
- 在数月或数年的积累中建立领域结构感；
- 对 AI 生成的理解保持证据控制权；
- 通过自托管保留数据、模型选择与观察历史。

## 产品范围

V2 覆盖：

- 以观测域组织用户长期关注的世界；
- 以星域观测台作为默认首页和主要操作空间；
- 以时间播放与变化层呈现星域演化；
- 以稳定真实事件和故事身份支持跨快照连续阅读；
- 串联星域、故事、简报、证据和来源记录；
- 提供当前观测域内按日连续复盘原始来源的播放工作台；
- 提供全局信源管理与来源记录资料库；
- 将任务、Worker、存储、模型和系统配置收敛到运行层；
- 通过 Web、REST、WebSocket 与 MCP 让同一语义世界可被人和智能体使用；
- 保持单用户、自托管、长期积累和证据优先的产品前提。

## 边界

- 当前语义对象以可验证的结构化市场与公共事件为主，不把观点、方法论或概念强行伪装成事件；
- 若未来引入 Claim、Concept 等对象，必须同时定义身份、证据与展示协议；
- 语义距离不等于因果、影响强度、投资相关性或地理距离；
- 系统不提供投资预测、交易建议或无证据的趋势结论；
- 不建设社区、内容推荐、多租户组织协作或复杂权限体系；
- 不用跨观测域前端拼接制造虚假的全局宇宙；统一跨域空间需要独立的身份与投影协议；
- 不为了产品改名复制采集、分析或任务链路。

这些边界用于保护产品可信度，不用于缩小星域体验本身。

## V2 成功标准

- 用户打开 Raelyn 后，第一眼看到的是关注世界的当前形态和变化，而不是后台处理面板；
- 用户能够播放一段时间并直观看见星域密度、主题与故事如何发展；
- “新发生”“新进入星域”和“自上次观察以来更新”在产品中有不同且准确的语义；
- 真实事件和故事在跨快照更新后仍可连续回访；
- 任意星点、航迹和简报结论都能返回明确证据与原始来源；
- 简报、故事、星域和事件列表共享同一对象身份与时间上下文；
- 用户可以在当前观测域中按日浏览可播放记录，并在离开后恢复日期、记录与播放位置；
- 信源和来源记录完整可管理，但不会把产品叙事拖回媒体库存管理；
- 运行问题只在需要处理时浮现，并能定位到受影响的观测域或对象；
- 用户在长期使用后能形成对自己关注领域的空间记忆和故事记忆。

## 产品命题

> Raelyn V2 是一张持续演化、可以回到证据的私人语义宇宙；下载、转写、任务和信源管理只是维持这座观测站运行的基础设施。
