# 项目愿景 V2

## 文档状态

本文定义 `raelyn` 的 V2 产品方向，并将“当前实现事实”与“目标产品体验”分开描述。

- 当前代码行为、接口和数据口径仍以 [架构总览](architecture/overview.md)、[REST API 设计](api/rest.md)、[数据模型与存储布局](architecture/data-model.md) 和 [事件语义星域](architecture/event-graph-analysis.md) 为准。
- V2 信息架构和页面关系见 [V2 信息架构](product/information-architecture-v2.md)。
- V2 首页与星图的布局意图见 [首页与星图低保真线框](ui/wireframes-v2.md)。
- V2 产品术语不要求内部表名、API 路径和任务类型立即同步改名；实施时应通过分阶段迁移避免破坏现有链路。

## 业务目的

`raelyn` 是一个面向单用户、自托管场景的语义观测系统。它持续采集用户选定的 YouTube / B 站信源，把视频转换为可检索的文本、可追溯的事件、主题与故事关系，并通过周期简报和事件语义星域帮助用户理解一个关注领域中发生了什么。

下载、转码和转写是系统的感知层；事件、故事、简报与语义星域是产品的认知层。

## 产品定位

**Raelyn 是用户的私人语义观测站。**

一句话定位：

> Raelyn 持续监听用户选择的信源，把不断流入的视频凝结为可追溯的事件、故事与简报，并更新一张可以长期探索的事件语义星域。

V2 不再以“下载了多少视频”为主要价值表达，而以以下问题为中心：

- 我的关注领域发生了什么？
- 哪些内容描述的是同一件事？
- 一件事如何延续，又获得了哪些新证据？
- 当前结论来自哪些视频、转写片段和原始来源？

## 目标用户

Raelyn 面向需要长期跟踪公开音视频信源的个人研究者、分析者和深度信息消费者。

这类用户通常具有以下特征：

- 愿意主动选择和维护自己信任或需要关注的信源；
- 希望减少重复观看、跨来源去重和人工整理的时间；
- 需要按天、周或月形成可持续阅读的领域简报；
- 希望通过主题、实体、事件和时间探索长期内容，而不只依赖关键词搜索；
- 要求 AI 生成的事件、关系和摘要能够返回原始证据；
- 接受自行部署和维护系统，以换取数据控制权和长期积累。

## 当前事实基线

当前系统已经具备以下基础能力：

- 信源管理、增量同步、视频下载、字幕标准化、ASR、转写润色、视频笔记与资产存储；
- Playlist 对信源集合、图片、简报粒度和独立提示词的聚合；
- 按日、周、月生成和读取 Markdown 简报；
- 从 transcript 抽取事件记录，并保存实体、关系、证据、模型口径和复算依据；
- 对已确认事件生成语义向量，并保守归并为 canonical 真实事件；
- 在不可变快照中保存两级主题、故事关系、实体索引和固定三维语义坐标；
- 通过 HTTP、WebSocket 和 MCP Server 读取数据或触发异步任务；
- 由 API、Worker、Scheduler 和统一 Job 体系组成的长期运行链路。

当前边界同样明确：

- 事件语义星域按 Playlist 独立构建，不存在跨 Playlist 的统一 canonical 身份和全局投影；
- 地图时间只控制观察窗口，不参与 X/Y/Z 语义坐标；
- `event_time` 表示事件发生时间，`available_at` 表示系统获得记录的时间，两者不能互相替代；
- 当前事件抽取口径面向结构化市场与公共事件，不等同于通用观点、概念或任意知识抽取；
- 当前不提供市场 Regime、收益率分析、语义漂移、变化点识别或预测能力。

## 核心产品对象

### 观测域

用户长期关注的主题空间，由一组信源、观测说明、简报策略和事件星域共同组成。

当前实现对象为 Playlist。V2 界面使用“观测域”表达其产品职责，但首阶段不要求修改 `playlist` 表、既有 API 或任务类型。

### 信源

持续提供内容的频道或账号，当前由 Media 承载。信源负责定义系统观察什么，不直接代表结论。

### 来源记录

视频及其标题、描述、字幕、转写、音频和来源链接，当前由 Video 与 Asset 承载。来源记录是事件和简报的证据载体，不再是 V2 的产品叙事中心。

### 事件记录

一次内容分析产生的结构化事件陈述，保留事件时间、类型、实体、关系、置信度、抽取模型和证据引用。

### 真实事件

对多条事件记录进行保守归并后的 canonical 事件。证据不足时允许记录保持独立，不为了减少点数而扩大误合并。

### 主题与故事线

- 主题表达语义空间中的邻近与归属；
- 故事线只表达有证据的延续、原因、响应或纠正关系；
- 普通语义邻近不自动形成故事关系。

### 观测简报

以观测域为范围，按日、周或月聚合来源文本形成的领域总结。简报中的结论应逐步支持定位到事件、证据和原始来源。

### 事件语义星域

用于浏览主题、真实事件、故事与证据的固定三维语义空间。星点代表 canonical 真实事件；坐标表达语义关系，不表达物理位置、时间、因果或影响强度。

## 核心用户循环

1. 用户创建观测域，选择信源、关注问题、简报粒度和提示词。
2. 系统持续同步内容，并完成下载、转写和文本整理。
3. 系统从文本中抽取事件，生成向量，归并真实事件并更新主题、故事和星域快照。
4. 用户回到观测域，先了解新发生、新收录、待审核和持续发展的内容。
5. 用户从简报、事件流或语义星域进入具体事件。
6. 用户下钻到事件记录、实体、证据片段和原始视频，验证自己的理解。
7. 用户调整信源、提示词或观察范围，进入下一轮持续观测。

其中：

- “新发生”依据 `event_time`；
- “事件记录的新收录”依据 `MarketEvent.available_at`，来源视频入库时间则使用 `Video.created_at`；
- 历史回填可以形成“新收录”，不能因此被描述为“刚刚发生”。

## V2 目标体验

### 今日观察

进入系统后优先回答“当前观测域发生了什么”，而不是展示文件数量和基础设施占用。首页围绕当前星域快照、新发生事件、新收录记录、待审核事件和最新简报组织。

### 星图探索

事件语义星域成为一级工作面，而不再隐藏在播放列表详情的次级入口中。用户可以围绕主题、真实事件、实体、故事关系和时间窗口持续建立空间记忆。

### 事件验证

事件流同时支持“发生时间”和“收录时间”两种明确口径。任意事件都可以下钻到记录、证据片段和原始视频。

### 故事跟踪

用户可以阅读由有证据关系组成的故事线。独立故事目录、关注状态和回访增量属于 V2 目标能力，不视为当前已实现事实。

### 简报阅读

简报成为独立阅读入口，并与事件、星点和来源记录形成双向定位，而不只作为播放列表详情中的周期面板。

### 运行治理

任务、Worker、服务健康、模型调用、存储与系统配置收敛到运行层。正常状态下不占据产品主界面；异常时提供清晰、可行动的提示。

## 产品原则

### 事件优先

媒体文件和处理状态服务于事件理解，不占据产品叙事中心。

### 证据优先

摘要、事件和故事必须能够回溯到事件记录、转写片段及原始来源。生成性文案只能作为有版本、有来源的解释层，不能改写事实层、归并结果或证据关系。

### 保守归并

允许证据不足的事件保持独立，不为减少点数、制造故事或改善视觉效果而错误合并。

### 稳定语义地理

星域帮助用户形成长期空间记忆。已有事件在算法口径稳定时应尽量保持坐标连续；发生 rebase 时必须明确提示连续性中断。

### 时间语义准确

事件发生时间、平台发布时间、内容时间和系统收录时间各自承担明确职责，不能为了界面便利混为一条时间轴。

### 诗意服务于理解

星域隐喻用于品牌、空间探索和状态表达；操作层继续使用事件、证据、信源、简报等清晰名称。视觉层不得添加会被误认为数据的装饰星点、虚构连线或因果暗示。

### 持续而可观测

自动同步和分析应长期运行。失败、覆盖率、任务状态和快照构建状态必须可见，但属于运行治理和数据质量层，而非主要价值层。

### 用户控制边界

观测范围、信源、监控开关、提示词和简报策略由用户明确配置。来源权重、自动可信度等会改变结果口径的能力，必须在存在可验证目标后再引入。

## V2 范围

- 将信息架构从“媒体处理功能集合”调整为“观测域驱动的事件理解系统”；
- 以观测域作为信源、事件、星域和简报的主要工作上下文；
- 让首页优先呈现领域变化、事件、故事、待审核内容和最新简报；
- 将事件语义星域提升为一级入口；
- 串联“简报或星域 → 真实事件 → 事件记录与证据 → 原始视频”的完整路径；
- 将信源、来源记录和转写收敛到资料库；
- 将任务、服务状态、存储、MCP 和底层配置收敛到系统区域；
- 保留现有采集、转写、事件分析、简报、API、WebSocket、MCP 与任务体系，不另建平行处理链路；
- 保持单用户、自托管和本地长期维护的产品前提。

## 后续扩展边界

若未来需要让方法论、观点和概念类内容进入语义星域，应先定义与 Event 并列的 Claim、Concept 等可验证语义对象、证据协议和展示规则，再扩展事实模型。不能仅通过修改页面名称，把现有市场事件模型描述为通用知识图谱。

跨观测域探索应先从“观测域目录、跨域检索和命中后进入对应星域”开始。统一全局星图需要跨域 canonical 身份、统一投影、资源预算和查询口径，首版 V2 不通过前端拼接多个独立快照实现。

## 非目标

- 不建设多租户、组织协作、复杂权限和审计体系；
- 不扩展为通用内容管理、社区、社交或推荐平台；
- 不承诺覆盖所有视频平台、DRM、付费或强交互内容；
- 不把语义距离解释为真实因果、影响强度或市场关联；
- 不提供投资预测、交易建议、收益率分析、Regime、语义漂移或变化点结论；
- 不在缺少可验证目标时引入来源权重或自动可信度评分；
- 不要求首版 V2 建立跨观测域的统一全局星图；
- 不以 AI 输出替代证据审核，也不隐藏不确定性和失败状态；
- 不为了产品改名另建第二套异步执行框架。

## V2 判断标准

- 用户进入系统后，首先看到的是“关注领域发生了什么”，而不是存储了多少文件；
- 任意事件结论都能沿明确路径回到记录、证据片段和原始来源；
- 星域承担稳定的语义导航职责，而不是装饰性可视化；
- “新发生”和“新收录”在文案、筛选、排序和时间轴中始终可区分；
- 新的产品表达不改变现有事件时间、归并和证据边界；
- 原有自动采集与处理链路在产品重构后仍可持续、可观测地运行；
- 任务、存储和服务健康在正常状态下退居运行层，在异常时仍能快速定位；
- 当前能力与目标能力在文档和界面中保持清楚边界。
