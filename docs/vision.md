# 项目愿景

## 项目定位

`raelyn` 是一个基于 `yt-dlp + ffmpeg + FastAPI` 的单用户媒体订阅、视频采集与文本整理系统，面向 YouTube / B 站内容的持续发现、下载、转写、聚合和后续分析。

项目目标是把“添加媒体 -> 同步资料与视频 -> 下载视频与产物 -> 聚合到播放列表 -> 生成周期简报”串成一条可持续运行、可观测、可在本地长期维护的链路。

## 当前核心能力

- 支持添加、导入、导出媒体；媒体新增后默认不启用监控，需要显式开启。
- 支持同步媒体资料与视频列表；已启用监控的媒体会由 `scheduler` 分钟级投递增量同步任务。
- 支持 YouTube / B 站视频下载，保存视频、音频、缩略图、字幕、文字稿等产物。
- 支持字幕标准化、音频转写（可选 ASR）、LLM 转写润色与视频笔记生成。
- 支持播放列表聚合，可为播放列表配置头像、背景图、简报粒度和独立提示词。
- 支持按天 / 周 / 月生成 Markdown 简报，并在播放列表详情页直接查看。
- 支持通过 HTTP / WebSocket / MCP Server 三种方式读取系统数据与触发异步任务。
- 支持可选的主站 API Bearer Token、平台 Cookies、会员视频下载开关，以及系统 / provider 暂停机制。

## 当前范围边界

- 单用户系统，不做多租户、权限审计与团队协作。
- 默认围绕“本地或受信任网络内部署”设计；主站 API 鉴权与 MCP 鉴权是可选保护措施，不是完整的公网暴露方案。
- 默认优先公开可访问内容；通过 Cookies 可以改善登录态、年龄验证、风控和部分会员场景，但不承诺覆盖所有受限内容。
- 简报产物以 Markdown 为主，围绕播放列表做周期聚合，不追求通用内容管理平台能力。

## 当前不做的内容

- 多用户权限体系、审计日志、组织级管理。
- 平台侧付费 / DRM / 强交互内容的完整覆盖。
- 与核心媒体采集链路无关的社区化、社交化或复杂推荐功能。
- 与现有 Job 体系无关的第二套异步执行框架。
