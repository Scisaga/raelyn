# 项目愿景

## 项目定位

`raelyn` 是一个基于 `yt-dlp + ffmpeg` 的单用户媒体订阅与视频采集系统，面向 YouTube / B 站内容的订阅、下载、整理与后续文本分析。

项目目标是把“发现新视频、保存视频与音频、抽取字幕或转写、按播放列表做日级汇总”串成一条可持续运行的链路。

## 核心能力

- 支持 YouTube / B 站视频与字幕下载
- 支持订阅内容管理，添加/删除媒体，并同步媒体的基本信息，如头像、名称、描述、订阅数量等
- 支持批量下载媒体的全部视频
- 支持分钟级同步媒体最新发布的视频
- 下载后分离视频音频并单独保存到 S3
- 如果有字幕，将字幕内容保存为标准文字内容并存到 S3
- 支持配置 `qwen3-asr` 服务地址；如果视频没有中文字幕，支持调用该服务解析音频得到文字内容并存到 S3
- 支持查看已经下载的视频，并按照时间 / 媒体筛选
- 支持通过 HTTP 接口获取视频 / 音频 / 文字内容
- 支持播放列表功能，可配置播放列表包含的媒体，并围绕播放列表聚合视频内容
- 支持配置 Ollama 服务地址，基于播放列表按天对采集到的视频文字内容进行汇总分析，产出简报

## MVP 范围

当前文档范围以内，MVP 主要聚焦：

- 单用户使用，不做多租户
- 覆盖 YouTube / B 站两个平台
- 以媒体订阅、视频发现、下载、字幕 / 转写、播放列表聚合、按天简报为主线
- 简报产物以 Markdown 为主
- 播放列表在 MVP 中先支持“添加媒体”的集合能力，复杂播放规则后续扩展

## 当前不做的内容

以下内容不属于当前主文档范围，后续如果成为正式决策，再进入专题文档或 ADR：

- 鉴权、权限审计、多用户隔离
- 需要登录或付费才能访问的媒体内容
- 超出 MVP 的播放列表行为，例如已播放记录、自动播放最新、复杂同步规则
- 与核心媒体采集链路无关的产品化功能扩展
