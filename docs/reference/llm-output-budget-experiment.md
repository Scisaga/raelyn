# LLM 有限输出预算实验

## 业务目的

修复事件抽取的重复展开、简报缺章/空正文/丢来源问题，保留有限输出预算，避免把输出截断简单解释为需要更大的 token 上限。

## 实验输入与边界

2026-09-09，使用当前实际服务 `qwen3.8:latest`、Ollama 0.33.2、上下文 32768。只读复用最近一周失败任务的字幕、来源与简报模板，不创建上游 domain 数据；真实模型请求串行执行，响应保存在实验目录，业务库不写入实验结果。

事件样本来自全部 10 个历史截断任务，包括 6 个第一财经短视频、PIIE、Bruegel 和 2 个 IMF 视频；按原分块读取全部文本。历史模型名称与提示词版本可核对，但可变模型别名无法证明底层权重从历史失败时至今没有变化。

简报选择 4 个代表周期：无需摘要的缺章样本、空/过短正文样本、缺四章样本、分段摘要缺链接样本。采集时其中一个周期已有新增上游文本（原 59900 字变为 68630 字），其余三个来源总字符数与历史记录相同。实验不能逐条证明全部 89 个历史简报的根因。

## 对照结果

| 样本与条件 | 输出 token | 结束原因 | 结果 |
| --- | ---: | --- | --- |
| 111 字字幕，原 JSON 模式，上限 4000 | 4000 | length | 同一个 video_id 重复展开 17 次，JSON 不完整 |
| 相同输入，仅将上限提高至 8000 | 8000 | length | 继续重复，仍不完整 |
| 相同输入，仅修改温度或重复惩罚 | 306–4000 | stop / length | 部分请求结束，但换 seed 仍出现重复 video_id；不能作为可靠修复 |
| 相同输入，约束响应容器，上限仍为 4000 | 309 | stop | 一个视频、一个事件、合法 JSON |
| 缺章简报，think=true，上限 8000 | 2456 | stop | 缺三个章节，未达到输出上限 |
| 相同简报，章节字符串 schema，think=true | 2414 | stop | 只有思考内容，正文为空，未达到输出上限 |
| 相同简报，原 Markdown 提示词，think=false | 3012 | stop | 章节完整 |
| 相同简报，章节字符串 schema，think=false | 1594 | stop | 章节完整，输出更紧凑 |
| 历史缺链接的摘要批次，原调用，上限 2500 | 728 | stop | 未保留任何真实来源 URL |
| 相同批次，事实与受限来源字段，上限仍为 2500 | 605 | stop | 来源和摘要校验通过 |

首轮扩大验证还发现：章节字符串 schema 虽能保证章节存在，仍可能把 URL `ohzV9ltTzI8` 漏写成 `ohzVltTzI8`。最终实现将每条要点的正文与来源分开，来源字段只能从本次输入 URL 中选择，由应用渲染 Markdown。不会补空章节或猜测修复 URL。

## 实现与预算

- 事件抽取维持 4000 token，JSON schema 限制视频记录数量、允许的 video_id 与每视频最多 4 个事件；解析器拒绝重复 video_id，证据与实体校验继续执行。提示词中互相冲突的对象/关系数量限制已统一，版本为 `llm_event_v5_bounded_response`。
- 摘要维持 2500 token，每批最多 8 条关键事实，每条最多 120 字、1–3 个真实来源；仍按来源顺序串行归并，最多 4 轮。
- 最终简报显式限制为 8000 token，按模板章节返回 1–5 条要点及受限来源字段，再渲染 Markdown；两阶段均关闭显式思考。没有规定章节的自定义模板保留单个 `markdown` 正文字段。
- 默认输入预算为 22937，输出 8000 仍在 32768 上下文内留有余量；自定义输出预算会进一步收紧输入预算。8000 是当前模板/上下文的有限默认额度，不代表所有模型或任意模板的最优值。
- `0`、`-1` 不允许作为事件或最终简报输出预算。明确截断的响应不能进入后续合成或发布，也不以同一额度反复修复。
- 流式和非流式均保留结束原因；简报 job_event 逐次记录阶段、输入/输出 token、正文/思考字符数，不把原始正文或认证信息写入日志。

## 最终验证结果

| 验证范围 | 实际调用/分段数 | 输出 token 范围 | 结果 |
| --- | ---: | ---: | --- |
| 10 个历史失败视频的全部分段 | 23 | 14–1574 | 全部正常结束；JSON、视频唯一性、事件数和证据 ID 校验通过 |
| 4 类简报样本的摘要阶段 | 10 | 587–736 | 全部正常结束；事实、来源及压缩效果校验通过 |
| 4 类简报样本的最终生成 | 4 | 1874–2278 | 全部正常结束；全部规定章节及真实 URL 校验通过 |

27 项直接相关回归测试及 3 项历史缺陷/配置边界校验通过；没有新增 mock。完整集成验证的 2 个测试方法包含上述所有分段与周期，响应缓存只用于重复校验，不重复消耗模型请求。

AI worker 已等待在途任务结束后重载为 `xh51:2037672:67715fcc`。随后通过正常任务入口执行两项业务恢复验证，均在第 1 次尝试成功：

- 事件抽取：`a05abaa5-4598-4113-bf57-620a802ad437`，写入当前 v5 的成功运行及 1 个事件。
- 简报生成：`19774ca6-f98c-40b8-ac38-665831dedfed`，执行 2 次摘要和 1 次最终合成，简报状态 `ready`，24 条引用，策略 `structured_brief_v2`。

每次简报调用均记录 `done_reason=stop`，实际输出未达到各自额度；AI 角色暂停已恢复。

## 历史失败任务恢复

2026-09-09，用户要求补做失败任务重试。以原周报中的 89 个简报、10 个事件抽取失败任务为固定范围，核对当前任务状态和业务产物后，通过现有重试与简报手动调度入口执行：

- 2 个已有成功产物的样本任务跳过重复生成。
- 51 个尚无活动恢复任务的失败任务执行手动重试：42 个简报、9 个事件抽取；复用原 job ID，按既有接口重置执行次数，保留 `manual retry requested` 事件。
- 46 个简报已有待执行任务，复用它们并按正常手动调度规则提前执行，避免重复生成。
- 88 个待恢复简报使用手动优先级 5；事件抽取保留已有优先级。输出额度、最大尝试次数及 worker 并发额度保持原配置。

截至 2026-09-09 06:42:38（北京时间），99 项恢复目标中：4 项成功（含此前的 2 项样本恢复）、1 项运行中、94 项排队，尚无本轮恢复失败。已核对成功事件的 v5 运行产物及成功简报的 `ready` 状态；排队和运行中不计为恢复成功。复用已有任务的历史失败 job 保留原状态，通过恢复任务 ID 关联实际结果。

批量执行前快照、99 项原任务与恢复任务的对应关系、操作记录和只读核对脚本保存在 `/tmp/raelyn-llm-retry-20260909/`。`recover.py` 是本次操作记录，已执行后禁止整批重复调用；后续可通过 `PYTHONPATH=backend ./.venv/bin/python /tmp/raelyn-llm-retry-20260909/status.py` 核对进度。代码更新本身不会自动重启已终止失败的历史任务，本次恢复属于明确触发的手动重试。

## 复现与回归

采集及定向验证命令见 [运行说明](run-and-deploy.md#llm-有限预算定向实验)。现场原始输入、响应、耗时与对照脚本保存在 `/tmp/raelyn-llm-budget-20260909/`。模型请求耗时包含共享服务排队与缓存影响，仅用于观察，不能作为严格性能基准。

接口依据：[Ollama 生成 API](https://docs.ollama.com/api/generate)、[结构化输出](https://docs.ollama.com/capabilities/structured-outputs)。采样对照参考 [Qwen 同架构模型参数建议](https://huggingface.co/Qwen/Qwen3.5-27B#best-practices)；实测采样调整未稳定解决重复，因此最终实现保留原采样参数，通过输出结构约束修复。
