# Raelyn V2 信息架构

## 文档状态

本文定义 V2 的目标信息架构、页面职责、上下文关系和关键交互，不表示所有页面及接口已经实现。

- 产品定位与范围见 [项目愿景 V2](../vision.md)。
- 当前已经实现的 UI 行为见 [UI 设计总览](../ui/overview.md)。
- 首页与星图的布局意图见 [首页与星图低保真线框](../ui/wireframes-v2.md)。
- 当前接口事实见 [REST API 设计](../api/rest.md)。

本文使用以下状态标记：

- **可复用**：现有数据和接口已经能够支撑主要体验；
- **界面重组**：现有能力可用，主要工作是入口、路由和组件重组；
- **需新增读取能力**：事实数据大体存在，但缺少面向页面的查询或聚合；
- **需新增产品状态**：当前没有对应持久化语义，不能只靠前端表现；
- **远期边界**：不属于首版 V2。

## 信息架构目标

V2 信息架构解决四个问题：

1. 让产品从“管理媒体处理流程”转向“理解关注领域发生了什么”；
2. 让 Playlist 从普通列表页升级为贯穿主要页面的观测上下文；
3. 让事件语义星域、事件流、故事和简报围绕同一组事实对象互相定位；
4. 将任务、存储、服务状态和底层配置从认知主界面收敛到运行层。

## 产品对象与现有对象映射

| V2 产品对象 | 当前实现对象 | 用户理解 | 首版处理 |
| --- | --- | --- | --- |
| 观测域 | `Playlist` | 一组长期关注的信源、简报策略与事件星域 | 界面改名，内部对象暂不改名 |
| 信源 | `Media` | 持续提供内容的频道或账号 | 收入资料库 |
| 来源记录 | `Video` | 视频及其平台元数据 | 收入资料库 |
| 证据资料 | `Asset`、transcript、来源链接 | 支撑事件与简报的原始材料 | 从事件和记录双向进入 |
| 事件记录 | `MarketEvent` | 一次内容分析形成的结构化陈述 | 保留审核状态与来源 |
| 真实事件 | `EventMapCanonical` | 多条记录保守归并后的现实事件 | 星图一级事实对象 |
| 主题 | `EventMapTopic` | 语义邻近的事件区域与主题团 | 星图远景与中景对象 |
| 故事线 | `EventMapStory` | 有证据的事件延续或响应关系 | 首版先阅读，关注能力后置 |
| 观测简报 | `Brief` | 日、周、月领域总结 | 提升为独立入口 |
| 星域快照 | `EventMapSnapshot` | 当前可浏览的不可变语义地图版本 | 保持 snapshot pin 语义 |

## 上下文层级

### 全局层

全局层不依赖某个观测域，负责：

- 观测域目录与创建；
- 全部信源和来源记录；
- 运行中心；
- 智能体接入；
- 系统设置；
- 未来的跨域搜索。

### 观测域层

“当前观测域”是 V2 主要工作上下文。用户选中一个观测域后，以下页面共享同一个 `domain_id`：

- 今日观察；
- 星图；
- 事件流；
- 故事线；
- 简报；
- 当前域的信源与设置。

切换观测域时，页面类型保持不变，内容、时间范围、筛选和快照上下文切换到新观测域。当前内部实现仍使用 `playlist_id`。

### 对象详情层

对象详情不成为新的孤立信息架构，而从工作面板中展开：

- 主题详情；
- 真实事件详情；
- 事件记录详情；
- 故事详情；
- 简报正文；
- 来源记录、转写和播放器；
- 信源详情；
- 任务详情。

详情必须保留返回路径和当前观测域上下文。

## 全局应用壳

### 左侧导航

左侧导航从上到下分为四段：

1. **品牌入口**
   - `RAELYN`
   - 副标识“私人语义观测站”
2. **观测域切换器**
   - 当前观测域名称；
   - 数据新鲜度或快照状态；
   - 打开观测域目录；
   - 新建观测域。
3. **工作导航**
   - 今日观察；
   - 星图；
   - 事件流；
   - 故事线；
   - 简报；
   - 资料库。
4. **系统导航**
   - 运行中心；
   - 智能体接入；
   - 设置。

观测域不再与“媒体、视频、任务”并列为普通功能菜单。它是工作导航的范围选择器。

### 顶部状态栏

顶部状态栏只承载与当前工作有关的内容：

- 页面标题和必要的面包屑；
- 当前观察窗口或页面时间口径；
- 全局搜索或命令入口；
- 最近更新时间；
- 系统异常入口。

队列数量、成功任务数、数据库和模型调用量不常驻顶部。正常时只显示一个健康状态；存在失败、暂停或服务不可用时才展开可行动提示。

### 主内容区

主内容区继续遵循全高面板、固定工具栏和独立滚动体：

- 页面主体贴边，不默认套大卡片；
- 工具栏固定在页面内容上方；
- 列表、画布和详情面板独立滚动；
- 页面切换不丢失当前观测域；
- 星图、事件和简报之间的跳转保留对象与时间上下文。

## 页面职责

| 页面 | 首要回答的问题 | 主要对象 | 状态 |
| --- | --- | --- | --- |
| 观测域目录 | 我正在观察哪些领域？ | Playlist、快照状态、信源预览 | 界面重组 |
| 今日观察 | 当前观测域最近发生和收录了什么？ | 真实事件、事件记录、简报、审核状态 | 需新增读取能力 |
| 星图 | 事件在语义空间中如何聚集和延续？ | Topic、Canonical、Story、Entity | 可复用并提升入口 |
| 事件流 | 哪些事件发生、收录或需要审核？ | MarketEvent、Evidence、Entity | 界面重组 |
| 故事线 | 哪些事件存在有证据的延续关系？ | EventMapStory、StoryEdge | 目录需新增读取能力 |
| 简报 | 当前域在各周期如何总结？ | Brief、事件引用、来源记录 | 列表接口可复用，界面需新增 |
| 资料库 | 系统观察了哪些信源和来源记录？ | Media、Video、Asset | 界面重组 |
| 运行中心 | 自动链路是否健康，哪里需要处理？ | Job、Worker、服务、存储 | 界面重组 |
| 智能体接入 | 外部智能体如何读取和触发 Raelyn？ | MCP tools/resources、鉴权 | 现有指南可复用 |
| 设置 | 系统和 provider 行为如何配置？ | AppConfig、Cookies、模型配置 | 可复用 |

## 观测域目录

### 内容

- 观测域名称、说明和标识；
- 信源数量与预览；
- 最近内容时间；
- 当前 ready 快照及构建状态；
- 事件覆盖率、未入图和失败数量；
- 最新简报状态；
- 打开上次使用页面；
- 新建、编辑和删除观测域。

### 视觉表达

- 默认缩略图优先使用该观测域当前 ready 快照生成的真实迷你星图或语义指纹；
- 人工头像或背景图作为识别标记，不代替数据状态；
- 无 ready 快照时使用明确空状态，不生成会被误解为真实星图的装饰图。

## 今日观察

### 页面目标

今日观察是当前观测域的回访入口，首屏回答：

> 自上一次观察以来，这个领域发生了什么、系统又收录了什么？

首版没有持久化 `last_seen` 时，文案必须退化为明确时间范围，例如“最近 24 小时收录”或“当前 12 个月窗口”，不能伪称“自上次访问”。

### 信息优先级

1. 当前观测域与观察窗口；
2. 当前星域缩略视图；
3. 新发生事件；
4. 新收录事件记录；
5. 待审核事件；
6. 最新观测简报；
7. 故事更新；
8. 数据质量与运行异常。

### 首屏布局

- 左侧主区域：当前 ready 快照的星图预览；
- 右侧信息流：新发生、新收录、待审核三个明确标签；
- 下方主区域：最新观测简报；
- 下方辅助区域：故事更新与数据质量摘要；
- 系统健康只在异常时占据显著位置。

### 当前与目标边界

- 观测域列表、事件列表、事件状态、地图 manifest、scene 和简报都已有读取能力；
- 跨对象合并的首页 payload 尚不存在，首版可组合请求，稳定后再增加专用读取模型；
- “故事更新”需要故事目录或面向当前窗口的故事查询；
- “自上次访问”需要新增用户本地或服务端阅读游标；
- “热点上升”“趋势拐点”不属于当前能力，不出现在首页。

## 星图

### 页面目标

星图是事件语义空间的一级工作面，帮助用户：

- 观察当前窗口内的主题结构；
- 选择主题并下钻代表事件；
- 选择 canonical 真实事件并查看记录、实体、证据和故事关系；
- 通过实体、类型、搜索和时间窗口缩小观察范围；
- 在固定语义地理中建立长期空间记忆。

### 布局

1. 顶部单行工具栏
   - 观察窗口截止日期；
   - 1/3/6/12 月窗口；
   - 事件类型；
   - 搜索与筛选；
   - 镜头模式与复位；
   - 数据质量入口。
2. 中央画布
   - 真实事件点；
   - 一级星域、二级主题和近景事件标签；
   - 当前选择、实体命中和有证据故事关系；
   - 无刻度空间参照网格。
3. 左侧按需抽屉
   - 搜索结果；
   - 实体筛选；
   - 六种对象说明。
4. 右侧按需详情
   - 发生了什么；
   - 所属主题与为何重要；
   - 事件记录；
   - 实体；
   - 证据；
   - 关联故事；
   - 来源记录定位。
5. 底部时间轴
   - 只使用事件发生区间；
   - 固定长度观察窗口；
   - 播放、平移和范围切换。

### 交互原则

- 普通点选不移动镜头；
- 只有“定位”或搜索结果显式聚焦；
- 时间窗口只改变可见性，不重新布局；
- 类型和实体筛选不改变坐标；
- 选中主题时保留成员语义色并弱化其他事件；
- 只绘制有证据的故事关系；
- 数据质量、构建进度和失败信息进入抽屉或异常条，不挤占主要地图解释。

## 事件流

### 三种工作模式

#### 新发生

- 按 `event_time_start/end` 过滤和排序；
- 用于回答现实世界在某个时间范围发生了什么；
- 没有可解释事件时间的记录不进入该视图。

#### 新收录

- 按 `available_at` 过滤和排序；
- 用于查看系统最近获得或历史回填的记录；
- 必须同时显示事件发生时间，避免误读。

#### 待审核

- 以 `draft` 为主要范围；
- 显示置信度、provenance 状态、实体和证据数量；
- 支持接受或拒绝；
- 接受后进入 embedding 和地图更新链路。

### 详情顺序

1. 发生了什么；
2. 事件时间与收录时间；
3. 类型、方向、幅度和超预期；
4. 实体和关系；
5. 证据片段；
6. 来源视频与转写定位；
7. 所属 canonical、主题和故事。

当前事件列表接口默认按 `available_at` 排序。独立“新发生”列表需要增加明确的时间过滤和排序能力，不能在前端对单页结果重新排序后冒充全量事件时间视图。

## 故事线

### 首版阅读体验

- 展示故事标题或基于成员事件形成的可解释标签；
- 展示起止时间、成员事件数和关系类型；
- 时间顺序展开成员事件；
- 每条边显示关系依据；
- 从故事成员定位回星图；
- 从事件详情进入所在故事。

### 当前与目标边界

- 当前可以从 canonical 详情读取相邻 story edge，并按已知 `story_id` 读取故事详情；
- 当前没有观测域故事目录；
- 当前 `story_id` 由快照派生，只在该快照内有效；跨快照展示“故事更新”前，需要新增稳定身份、谱系或差异计算能力；
- “关注故事”“新增证据提醒”和“自上次观察新增成员”需要新增持久化产品状态；
- 生成性故事摘要只能作为 versioned narrative，不改变 story member 或 edge。

## 简报

### 内容

- 当前观测域的日、周、月简报列表；
- 周期、状态、生成时间和正文预览；
- 阅读、复制、打开原文、重新生成；
- 逐步增加事件和来源引用；
- 从引用定位到星点、事件记录和来源视频。

### 当前与目标边界

- 简报列表和单条读取接口已存在；
- 当前 UI 主要在播放列表详情内阅读，需要提升为独立页面；
- 现有 Markdown 不保证包含稳定事件引用，双向定位需要扩展简报生成协议和引用结构。

## 资料库

### 信源

保留当前媒体管理能力：

- 新增、导入和导出；
- 同步近期或全部历史；
- 监控开关；
- provider 状态与自动停用原因；
- 所属观测域。

### 来源记录

保留当前视频列表和播放器能力，并调整信息层级：

- 平台与内容时间；
- 下载、字幕、转写和事件处理状态；
- 所属信源与观测域；
- 已抽取事件数量；
- 播放器、转写和资产；
- 从转写片段定位关联事件。

### 转写与证据

首版可以作为来源记录详情的子视图，不要求立即建立独立全局页面。独立全文与语义检索属于后续能力，不能使用三维 UMAP 坐标代替检索向量。

## 运行中心

运行中心合并现有任务页和概览页中的基础设施状态：

- 活动任务与完成任务；
- 类型、状态和时间筛选；
- 任务进度、错误、取消和重试；
- Worker 心跳与角色；
- 数据库、对象存储、ASR、Embedding、LLM 健康；
- 存储占用与模型调用；
- provider 暂停和系统暂停；
- 观测域事件覆盖与星域构建状态。

正常状态只在全局壳显示一个健康指示；异常时提供直达具体问题的入口。

## 智能体接入

“MCP Server”在产品导航中命名为“智能体接入”，页面继续说明：

- 连接地址和 Bearer 鉴权；
- tools 与 resources；
- VS Code、Codex CLI、OpenClaw 等接入方式。

当前 MCP 主要覆盖媒体、视频、播放列表、简报和任务。事件、主题、实体、故事和星图搜索工具属于 V2 目标能力，未实现前不能写入“当前可用工具”。

## 搜索架构

### 当前可用

- 信源与视频关键词搜索；
- 播放列表搜索；
- 单个星域快照内的 canonical、topic 和 entity 搜索。

### V2 目标

全局搜索或命令面板按对象分组返回：

- 观测域；
- 信源；
- 来源记录；
- 简报；
- 当前观测域内的主题、真实事件和实体；
- 运行任务与设置命令。

跨观测域的 canonical 语义搜索需要新的检索表示和查询接口。三维投影坐标只用于布局，不能充当语义搜索索引。

## 状态与时间语义

### 必须保留的状态

- 当前观测域；
- 当前页面；
- 当前快照 ID；
- 星图观察窗口；
- 事件流时间口径；
- 当前主题、实体、事件或故事选择；
- 详情返回路径。

### 时间标签

界面统一使用以下明确标签：

- `发生于`：`event_time_start/end`；
- `内容时间`：选出的 `content_published_at`，缺失时按既有规则回退；
- `平台发布`：`published_at`；
- `事件收录于`：`MarketEvent.available_at`；
- `来源入库于`：`Video.created_at`；
- `简报生成于`：简报生成时间；
- `快照完成于`：`EventMapSnapshot.finished_at`，观测域级最近完成时间可使用 `EventMapState.last_built_at`。

不使用没有口径的“时间”“最近”“今天发生”等模糊文案。

## 建议路由

以下是目标信息架构的建议路由，不表示当前接口或 SPA 已支持：

```text
/domains
/domains/:domainId/today
/domains/:domainId/map
/domains/:domainId/events
/domains/:domainId/stories
/domains/:domainId/briefs
/domains/:domainId/settings
/library/sources
/library/records
/operations
/integrations
/settings
```

实施时可先在现有 `playlist` 路由和 API 上建立界面映射，不要求同步修改数据库对象。若后续决定对外 API 改名，应一次性定义兼容窗口，避免长期维护两套含义相同的契约。

## 能力差距矩阵

| V2 能力 | 当前依据 | 差距 |
| --- | --- | --- |
| 观测域切换 | Playlist 列表与详情 | 增加全局持久上下文和入口 |
| 星图一级入口 | 完整 map manifest、scene、搜索和详情 API | 路由与页面重组 |
| 新收录事件流 | Playlist 事件列表按 `available_at` 排序 | 调整页面结构与文案 |
| 新发生事件流 | 事件包含 `event_time` | 需要服务端发生时间过滤和排序 |
| 待审核 | draft 列表与状态更新 | 提升为一级筛选 |
| 简报列表 | `/api/briefs` | 新增独立 UI 和域上下文 |
| 故事详情 | canonical 相邻边与 story detail | 需要故事目录读取能力 |
| 故事关注与增量 | 无持久化状态 | 需新增产品状态 |
| 今日观察聚合 | 数据分散在 stats、events、map、briefs | 需组合读取或专用 read model |
| 简报到事件定位 | 简报正文为 Markdown | 需结构化引用协议 |
| 来源记录到事件定位 | 事件保存 source video | 需增加反向查询与转写定位 |
| MCP 事件与星图访问 | 当前 MCP 未暴露事件对象 | 需新增 tools/resources |
| 跨域搜索 | 当前搜索均按对象或单个快照 | 需新增全局检索表示与接口 |
| 全局统一星图 | 当前快照按 Playlist 独立构建 | 远期边界，不在首版 V2 |

## 响应式与可访问性

### 桌面

- 展开侧栏；
- 星图画布、时间轴和右侧详情可同时显示；
- 今日观察使用主区域加右侧信息流。

### 平板

- 侧栏折叠为图标栏或抽屉；
- 星图详情作为覆盖层打开；
- 今日观察右侧信息流移动到星图预览下方。

### 手机

- 主要保障今日观察、事件阅读、简报、来源播放和 PWA；
- 星图保留基础浏览、搜索、时间窗口和事件详情，复杂多面板改为逐层抽屉；
- 不通过删减事件或改变坐标换取性能；
- 不支持 WebGL2 时显示明确边界，并提供事件列表入口。

### 可访问性

- 所有颜色编码同时提供文本、形状或标签解释；
- 键盘可以到达导航、搜索、主题标签、事件和详情；
- 支持 `prefers-reduced-motion`；
- 减少动态效果时停止自动播放、入场和持续动画；
- 时间、ID 和数值使用稳定的等宽或 tabular 排版；
- 星图必须提供事件流作为非空间替代入口。

## 验收标准

- 用户选择观测域后，可以在今日观察、星图、事件、故事和简报之间切换而不丢失范围；
- 首页首屏优先表达事件、简报和证据，而不是媒体总量和基础设施占用；
- 星图可以从一级入口进入，且现有快照、时间、筛选和详情语义不回退；
- 新发生与新收录在数据口径和界面文案中明确分开；
- 任意已展示事件均存在返回记录、证据和来源的路径；
- 正常系统状态退居运行层，异常仍可一跳进入处理页面；
- 目标能力和当前能力在页面、文档和验收中明确区分；
- 首版不伪造跨域 canonical、全局统一星图、趋势拐点或预测能力。
