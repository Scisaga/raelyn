# Raelyn V2 能力状态与后续缺口

## 文档职责

本文只记录 V2 产品定义与当前实现之间仍然存在的差距。已经落地的能力不再继续写成“未来目标”。产品高度由 [V2 产品愿景](../vision.md) 定义，界面结构由 [V2 信息架构](information-architecture-v2.md) 和 [核心线框](../ui/wireframes-v2.md) 定义。

## 当前结论

V2 的核心观测闭环已经建立：

- 星域成为默认入口，观测域成为全局上下文；
- 用户观察游标可以恢复快照、事件时间窗、模式、筛选和选择对象；
- 变化集明确区分事件发生时间与系统认知时间；
- canonical 和 story 具有跨快照稳定身份、长期修订和变化历史；
- 故事目录、关注、已读状态和当前完整航迹可直接消费；
- 简报保存生成快照、生成口径，以及 canonical、story、evidence、source 四类结构化引用；
- 证据、来源记录、canonical 和简报可以双向定位；
- 星域变化可恢复变化所属快照并展示 before/after，显式有证据的 `corrects` 关系形成独立纠正变化；
- 信源与来源记录收敛到资料库，并支持当前域/全局范围；
- 来源播放已经拆为当前观测域的独立按日工作台，导航、URL 恢复、播放器/转写和星域生命周期彼此隔离；
- 观测域身份与安全删除、当前域信源范围、简报生成设置和运行命令已经迁移到各自唯一归属；
- 运行中心展示任务和四类独立覆盖率；
- REST、Web 与 MCP 使用同一套观测域、变化、历史、故事、简报和证据语义；
- 星域主显示使用类型化关系列与固定宽度二进制场景，不以全量 JSONB 作为渲染协议。

因此，后续工作不应再回到“把下载器换一套导航”的低目标。来源播放与观测域设置职责已经完成拆分，后续缺口集中在故事人工修订、结构化叙事引用、证据定位、混合搜索、规模验证和多设备状态语义。

## 已落地的目标契约

| 契约 | 当前实现 |
| --- | --- |
| Observation Cursor | `domain_observation_cursor` 与 `/api/domains/{id}/observation/cursor` |
| Field Change Set | `event_map_change` 与稳定 `(observed_at, id)` 游标 |
| Canonical History | 长期修订、正规化成员索引、merge/split lineage |
| Story Identity / Revision | 稳定身份、修订、变化、关注、阅读位置和当前航迹 |
| Domain Observation Feed | 新发生、认知变化、故事更新、待验证四个独立集合 |
| Structured Brief References | `brief.snapshot_id`、`generation_basis`、`brief_reference` |
| Evidence Navigation | 来源记录、字符区间、精确分段播放与反向引用 |
| Semantic MCP Objects | 观测域、变化、canonical、topic、story、brief、evidence 与分组搜索 |

## 仍需增强的产品能力

### 一、故事质量与人工修订

自动故事已经升级为以稳定锚点组织的证据事件图：语义相似度只负责候选相容性，`continuation/causes/response/corrects` 分别需要阶段、命题或显式关系证据；分支不再被压成线性链，并输出成熟度与质量分。稳定身份只在同算法版本、同锚点和保守成员重叠下延续。当前仍缺少：

- 人工合并、拆分、命名、隐藏和关系纠正；
- 自动故事与人工策展故事的并存规则；
- 故事冲突、证据反转和结论撤回的显式表达；
- 对一次 merge/split 为什么发生的面向用户解释。

### 二、结构化简报的叙事绑定

当前简报会从本次输入视频的 verified evidence 出发，建立 canonical、story、evidence 与 source 四类引用，固化生成快照和口径，并支持从 canonical、topic、story 与 evidence 反查、跳转到正文锚点。仍需增强：

- 让 LLM 正文段落在生成协议中直接声明引用，而不是在正文末尾追加引用清单；
- 把 story 引用从故事级进一步细化到某一条关系边；
- 当引用对象被纠正、合并或拆分后，在旧简报中展示历史口径与最新解释的差异；
- 在正文锚点之外进一步高亮该引用对应的完整论证范围。

### 三、证据播放定位

当前只有来源提供精确分段时间时才返回播放秒数；其余情况保持可靠的字符区间，不做比例估算。新快照还冻结 transcript asset id 和片段 SHA-256，检查器可区分当前、已被新版本替代与不可用的转写来源。后续应补齐：

- transcript segment 与字符 offset 的稳定映射表；
- 字幕版本变化后的 offset 迁移或失效说明；
- 多段证据、冲突证据和来源版本差异的统一检查器。

### 四、语义搜索深度

当前搜索可以按观测域、主题、真实事件、故事、实体、简报、信源和来源记录分组，并返回共享深链接，但主要是结构化文本检索。仍需增强：

- 关键词、全文、embedding 和对象关系的混合召回；
- 搜索结果的证据覆盖、时间口径和对象版本排序；
- 跨观测域搜索时保持各域 canonical 身份隔离，不制造虚假的全局同一性。

### 五、规模与冷启动

星域显示已经绕开全量 JSONB：热字段位于关系列，API 流式编码 56 字节场景记录，浏览器使用 typed arrays 与 GPU 时间裁剪。剩余的底层优化点是：

- `market_event_embedding.vector` 仍以 JSONB 保存，影响快照构建输入吞吐但不影响地图显示；
- 冷客户端首次请求仍由 API 从类型化列编码场景，可在实测 CPU 成为瓶颈后固化为不可变对象存储资产；
- 长期修订和变化集增长后需要基于真实数据量评估分区、归档和全文索引，而不是提前拆出第二套数据库。

这些迁移必须采用双写/双读或加法投影，不得通过暂停现有任务、删除任务、重抽全部事件或删除历史视频完成。

### 六、观察状态的多设备语义

当前产品是单用户系统，一个观测域只有一个持久观察游标。若以后支持多设备独立阅读进度或多用户，需要先明确主体身份，再把游标和故事阅读状态扩为 `(principal, domain/story)`；不能在没有身份模型时伪造多用户能力。

## 不应退化的边界

- 星域不是仪表盘卡片，而是默认认知空间。
- 观测域不是播放列表换名，而是持续观察和恢复上下文的边界。
- “新发生”不能与“系统刚认知”混为一谈。
- story 不能由三维邻近自动推断为因果关系。
- 简报不能重新退化为与语义对象割裂的 Markdown 文件。
- 资料库不能重新占据一级产品中心，但必须保留完整信源与来源记录管理能力。
- 来源播放不能因旧 `playlist` 技术对象退场而被删除；它必须作为当前观测域按日复盘原始材料的独立工作台存在。
- 为性能优化可以增加投影、索引和二进制旁路，不能删除证据正文、长期历史或既有来源记录。
