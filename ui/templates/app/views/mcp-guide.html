MCP Server 接入说明

本项目提供的是一个独立运行的 MCP Server。这里从客户端如何接入这个 Server 的角度，说明连接参数、鉴权方式、验证步骤和可调用能力。前端页面路由是 /mcp-guide，真实 MCP endpoint 默认仍是 http(s)://<host>:<port><base_path>。
Role: MCP Server Transport: Streamable HTTP Auth: Bearer Token Process: 独立 MCP 服务

1. 开发工具接入

这个 MCP Server 使用 Streamable HTTP transport。 接入时提供 Server URL 和 Bearer Token 即可；地址格式统一为 http(s)://<host>:<port><base_path>。

连接信息

示例接入地址可写为 http://raelyn:8001/mcp； 远端部署时再替换为实际域名、内网 IP 或反向代理地址。 
Server URL: http(s)://<host>:<port><base_path>
Transport: Streamable HTTP
Authorization: Bearer <MCP_BEARER_TOKEN>

VS Code + Codex

Codex IDE Extension 与 Codex CLI 共用 ~/.codex/config.toml。 在 VS Code 中可从 Codex 扩展齿轮菜单进入 MCP settings > Open config.toml， 然后写入这个 server 配置。 
[mcp_servers.raelyn]
url = "http://raelyn:8001/mcp"
bearer_token_env_var = "MCP_BEARER_TOKEN"

Codex CLI

使用 CLI 添加后，VS Code 中的 Codex 扩展会直接复用同一份 MCP 配置。 
export MCP_BEARER_TOKEN=replace-with-your-token
codex mcp add raelyn \
  --url http://raelyn:8001/mcp \
  --bearer-token-env-var MCP_BEARER_TOKEN

OpenClaw

将配置写入 ~/.openclaw/openclaw.json，保存后重启 gateway。 Bearer Token 可通过 ${MCP_BEARER_TOKEN} 引用环境变量。 
{
  "mcpServers": {
    "raelyn": {
      "url": "http://raelyn:8001/mcp",
      "headers": {
        "Authorization": "Bearer ${MCP_BEARER_TOKEN}"
      }
    }
  }
}

openclaw gateway restart
如果客户端要读取 transcript 大文本，优先使用 get_video_transcript 或 raelyn://video/{video_id}/transcript/chunks/{chunk_index} 的分块方式，不要假设单次能安全拿完整文本。

3. Tools

查询类 tool 返回 JSON 可序列化对象；异步动作类 tool 只返回 accepted + job_id/job_ids，不会同步等待任务结束。
名称 说明 名称 说明
list_media 列出媒体对象。 get_media 读取单个媒体详情。
list_videos 按条件列出视频。 get_video 读取单个视频详情。
get_video_transcript 读取视频 transcript，支持分块。 list_video_assets 列出视频关联产物。
list_playlists 列出播放列表。 get_playlist 读取播放列表详情。
get_playlist_videos 读取播放列表下的视频集合。 list_briefs 列出简报产物。
get_brief 读取单个简报详情。 list_jobs 列出任务与执行状态。
get_job 读取单个任务状态。 get_video_context 聚合返回视频级上下文。
get_playlist_context 聚合返回播放列表上下文。 sync_media 投递媒体同步任务。
download_video 投递视频下载任务。 retranscribe_video 投递重新转录任务。
generate_brief 投递简报生成任务。

4. Transcript 与错误语义

客户端接入时最容易踩坑的是 transcript 分块和“未就绪”状态，这里需要按当前协议处理。

Transcript 选择顺序

先按 variant 选：polished 优先于 plain
同一 variant 内按 source 选：subtitle + zh
然后是 qwen3-asr + zh
最后才是历史遗留 source：speaches + zh
以上都没有时，再回退到最新 transcript asset

分块规则

默认 chunk_size=12000，最大 50000
优先在 chunk 末尾附近按最后一个换行切分
越界块返回 ok=false, status=not_found

错误语义

对象不存在：not_found
参数非法：invalid_argument
状态冲突：conflict
产物未就绪：ok=false, status=not_ready

5. 调用建议

对 Agent/LLM 场景，建议先把这个 MCP Server 当成聚合上下文入口，优先走高层 tool，再按需补读 resource。

先拿视频上下文

优先调用 get_video_context，确认 transcript / note 是否已经就绪，再决定是否继续读取 transcript chunk。

先拿播放列表上下文

周报/日报类总结优先调用 get_playlist_context，它已经聚合了周期边界、视频列表和 brief 状态。

异步动作不要轮询阻塞

download_video、 retranscribe_video、 generate_brief 都只负责投递任务，后续用 get_job 或现有 UI 任务页跟踪状态。
