VS Code + Codex

Bearer Token · 完整能力
Codex IDE Extension 与 Codex CLI 共用 ~/.codex/config.toml。在 Codex 扩展的 MCP 设置中打开该文件，写入右侧配置后重新加载工具列表。 
[mcp_servers.raelyn]
url = "http://raelyn:8000/mcp"
bearer_token_env_var = "MCP_BEARER_TOKEN"

Codex CLI

Bearer Token · 完整能力
先把 API Token 写入环境变量，再执行右侧命令。添加成功后，VS Code 中的 Codex 扩展会复用同一份 MCP 配置。
export MCP_BEARER_TOKEN=replace-with-your-token
codex mcp add raelyn \
  --url http://raelyn:8000/mcp \
  --bearer-token-env-var MCP_BEARER_TOKEN
读取 transcript 大文本时，优先使用 get_video_transcript 或 raelyn://video/{video_id}/transcript/chunks/{chunk_index} 分块读取。

4. Transcript 与错误语义

客户端接入时最容易踩坑的是 transcript 分块和“未就绪”状态，这里需要按当前协议处理。

Transcript 选择顺序

先按 variant 选：polished 优先于 plain
同一 variant 内按 source 选：subtitle + zh
然后是 qwen3-asr + zh
最后才是历史遗留 source：speaches + zh
以上都没有时，再回退到最新 transcript asset

分块规则

默认 chunk_size=12000，最大 50000
优先在 chunk 末尾附近按最后一个换行切分
越界块返回 ok=false, status=not_found

错误语义

对象不存在：not_found
参数非法：invalid_argument
状态冲突：conflict
产物未就绪：ok=false, status=not_ready

5. 调用建议

对 Agent/LLM 场景，建议先把这个 MCP Server 当成聚合上下文入口，优先走高层 tool，再按需补读 resource。

先拿视频上下文

优先调用 get_video_context，确认 transcript 是否已经就绪，再决定是否继续读取 transcript chunk。

先拿播放列表上下文

周报/日报类总结优先调用 get_playlist_summary，它已经聚合了周期边界、视频列表和 brief 状态。

异步动作不要轮询阻塞

download_video、 retranscribe_video、 generate_brief 都只负责投递任务，后续用 get_job 或现有 UI 任务页跟踪状态。
